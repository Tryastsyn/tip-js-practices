## Организация кода

- `task-service.js` — девять проверенных функций ПР2: создание, поиск, сводка, изменение статуса, переименование и удаление. Работает только с переданными массивами, не обращается к `document` и не хранит глобальный список.
- `task-selectors.js` — функция `getVisibleTasks(tasks, filter)`: возвращает новую выборку для фильтра `all`, `pending` или `completed`, не меняя входные задачи.
- `task-view.js` — отображение: `createTaskElement` создаёт карточку через DOM-методы и `textContent`, `renderTaskList` заменяет карточки в списке, `renderSummary` выводит сводку, `renderEmptyState` показывает или скрывает сообщение о пустом списке. Данные не изменяет и обработчики не назначает.
- `main.js` — состояние приложения, обработчики событий и `renderApp`.

**Где хранятся полный список и фильтр:** в `main.js`, в переменных `currentTasks` (все актуальные задачи) и `currentFilter` (выбранный режим). Видимая выборка не хранится, а вычисляется при каждой отрисовке через `getVisibleTasks(currentTasks, currentFilter)`.

**Где обрабатывается событие:** в `main.js`. `handleTaskListClick` назначен один раз на контейнер `ul#task-list` (делегирование): через `closest` находит кнопку и карточку, читает `data-task-id`, преобразует его в число, вызывает `setTaskCompleted` или `removeTask` и при успехе сохраняет `result.tasks` и вызывает `renderApp`. `handleFilterClick` меняет только `currentFilter`.

**Где вычисляется сводка:** в `task-view.js`, функция `renderSummary` вызывает `getTaskStats` из ПР2 для полного `currentTasks`. Показатель «Показано» равен длине видимой выборки.

## Отладка и клавиатура

**Точка останова:** `src/main.js`, строка 55, `const id = Number(card.dataset.taskId);` в функции `handleTaskListClick`. Действие: клик по тексту «Выполнена» на карточке задачи 1 «Изучить функции» (общий набор, фильтр «Все»; задача изначально выполнена). Значения получены в консоли Safari во время остановки и после шагов до строки 79.

| Значение | Результат |
|---|---|
| `event.target` | `<span class="action-label">Выполнена</span>` — вложенная подпись кнопки |
| `event.currentTarget` | `<ul id="task-list" class="task-list" aria-label="Задачи">` — контейнер с делегированным обработчиком |
| `card.dataset.taskId` | `"1"`, тип `"string"` |
| числовой `id` | `1`, тип `"number"` |
| `action` | `"toggle"` |
| найденная задача | id 1, `completed: true` |
| результат `setTaskCompleted` | `{ ok: true, tasks: Array }` — новый массив из 4 задач, у задачи 1 `completed: false` |

Путь события: клик по `span` → всплытие до `ul#task-list` → `closest("button[data-action]")` находит кнопку → `closest("li[data-task-id]")` находит карточку → `Number("1")` и проверка положительного безопасного целого → `findTaskById` и `setTaskCompleted` → `currentTasks = result.tasks` → `renderApp()` → `restoreTaskFocus(1, "toggle")`.

**Клавиатура:** `Tab` последовательно переводит фокус по ссылкам, кнопкам фильтров и кнопкам карточек; фокус виден. `Enter` и `Space` на кнопках «Выполнена», «Удалить» и на фильтрах выполняют то же действие, что и клик, ровно один раз. После изменения статуса фокус возвращается на кнопку «Выполнена» той же задачи. После удаления карточки фокус переходит на кнопку активного фильтра.

**Отказ для изменённого атрибута карточки** (значение `data-task-id` изменено через вкладку «Элементы»):
- `777`: «Выполнена» → сообщение «Задача с id 777 не найдена.»; «Удалить» → «Задача с таким id не найдена»; список и сводка не изменились.
- `4abc`: `Number("4abc")` даёт `NaN`, сообщение «Некорректный идентификатор задачи.»; данные не изменились, `4abc` не превратился в `4`.
- После выбора фильтра карточки пересоздаются из настоящего массива с правильными id, сообщение очищается.

## Вывод

Кратко описать результат, исправленные ошибки и различие между изменением данных и изменением DOM.
Функции ПР2 подключены к браузерному интерфейсу без изменения прикладной логики. Задачи отображаются карточками, созданными через DOM-методы и `textContent`; работают изменение статуса, удаление, три фильтра по статусу, сводка, счётчик «Показано» и два вида пустого состояния. Общий и индивидуальный наборы обслуживаются одним кодом. Проверки сервиса: 35 из 35, браузерные проверки: 36 из 36. Дополнительно выполнен фильтр по приоритету, который работает совместно с фильтром по статусу.

**Исправленные ошибки:**
- При первой вставке кода `main.js` был целиком заменён тремя функциями: пропали импорты, объект `elements`, переменные состояния, подписки и стартовый вызов `renderApp()`. Страница оставалась в состоянии «Набор ещё не загружен». Файл восстановлен полностью, заменены только заглушки.
- Страница сначала открывалась через расширение Live Server, а не через `npm start`. Работа переведена на сервер практики `http://127.0.0.1:5503/`, как требует методичка.

**Изменение данных и изменение DOM.** Данные приложения — это массив `currentTasks` в `main.js`; он меняется только через функции ПР2 (`setTaskCompleted`, `removeTask`) и только при `result.ok === true`. DOM — лишь отображение этого массива: `renderApp()` каждый раз заново строит карточки по `currentTasks` и выбранным фильтрам. Поэтому удаление `<li>` без изменения массива не удаляет задачу: при следующей отрисовке карточка вернётся. Фильтр, наоборот, меняет только видимую выборку, а не данные, поэтому «Все» возвращает скрытые записи, а общая сводка при фильтрации не меняется.
