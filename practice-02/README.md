## 4. Модель данных и функции

1.1Кратко описать поля задачи, правила валидации и назначение файлов.
1.2Для каждой операции указать, какой результат возвращается при успехе и ошибке.
Не требуется дублировать весь исходный код.

1.1
**Поля задачи.** Задача это объект с четырьмя полями:
- `id`: положительное безопасное целое число, уникальное в пределах списка;
- `title`: строка, после `trim()` длиной от 1 до 100 символов;
- `completed`: логическое значение, при создании всегда `false`;
- `priority`: `"low"`, `"medium"` или `"high"`, по умолчанию `"medium"`.

**Правила валидации.** Типы проверяются строго, без приведения: `"4"` вместо `4` и `"false"` вместо `false` отклоняются. Название очищается от пробелов по краям, внутренние пробелы сохраняются. Уникальность `id` проверяется в `addTask`, а не в `createTask`, потому что только `addTask` получает список. Ожидаемые ошибки возвращаются как данные `{ ok: false, error }`, а не как исключения.

**Назначение файлов.**
- `src/data.js`: исходные данные (`demoTasks`, `variantNumber`, `variantTasks`), без функций;
- `src/task-service.js`: девять прикладных функций над переданными данными, без вывода в консоль и без глобального списка;
- `src/main.js`: общий и индивидуальный сценарии, вывод результатов и обработка отказов;
- `checks.js`: готовые проверки, сравнивающие результаты функций с ожиданиями;
- `examples/functions-and-references.js`: шесть экспериментов с функциями и ссылками.

1.2
`createTask` при успехе возвращает `{ ok: true, task: новаяЗадача }`, при отказе `{ ok: false, error: "причина" }`.

Четыре функции изменения списка (`addTask`, `setTaskCompleted`, `renameTask`, `removeTask`) возвращают `{ ok: true, tasks: новыйМассив }` при успехе и `{ ok: false, error: "причина" }` при отказе. Функция ничего не печатает и не роняет программу: решение принимает тот, кто её вызвал.

Функции чтения не возвращают `ok` и ошибок не создают:
- `findTaskById` возвращает найденный объект задачи или `undefined`, если задачи нет;
- `getPendingTasks` возвращает новый массив невыполненных задач (пустой, если таких нет);
- `getTaskTitles` возвращает новый массив названий в исходном порядке (для пустого списка `[]`);
- `getTaskStats` возвращает объект `{ total, completed, pending, progress }` с числами (для пустого списка все поля равны `0`).




**Почему id не равен индексу:** заполнить.  
индекс показывает текущую позицию задачи в массиве и меняется при удалении других задач, а id идентифицирует задачу и остаётся прежним. Например, задача с id 4 стоит под индексом 1
**Почему getTaskStats возвращает число, а не строку с процентом:** заполнить. 
число можно использовать в расчётах и сравнениях, а округление toFixed() даёт строку и выполняется только при выводе в main.js. 
**Какие объекты копируются при изменении задачи:** заполнить.
создаётся новый массив и новый объект изменяемой задачи, остальные задачи переиспользуются по ссылке и не меняются.

## 9. Вывод

В ПР1 расчёты выполнялись над отдельными переменными, а в ПР2 задача представлена объектом, список задач массивом, а операции над ними вынесены в функции и ES-модули: данные в `data.js`, логика в `task-service.js`, сценарий и вывод в `main.js`.

Функции ничего не выводят, а возвращают значения: объект `{ ok, task/tasks, error }`, массив или сводку. Эти значения использует `main.js`: при успехе заменяет текущее состояние на `result.tasks`, при ошибке выводит сообщение и оставляет состояние прежним. Процент из `getTaskStats` возвращается числом и округляется только при выводе через `toFixed(1)`.

Неизменность данных проверена тремя способами: проверкой 33 в `checks.js`, сравнением снимка `JSON.stringify` для `demoTasks` и `variantTasks` до и после сценариев, а также в собственных проверках. Для изменений используются spread, `map` и `filter`, поэтому создаются новый массив и новый объект изменяемой задачи.

Исправлена ошибка в эксперименте 2: в стрелочной функции с фигурными скобками не было `return`, и `square(4)` возвращал `undefined`; после добавления `return` результат стал `16`. При реализации `createTask` пришлось исправить проверку типа: сравнение `typeof title !== String` всегда было истинным, правильно сравнивать со строкой `"string"`.
